ZERO-TRUST AGENT IDENTITY - REPRODUCIBLE OFFLINE ARTIFACT

Prerequisite:
Docker with Linux-container support.

Start from a clean checkout of the immutable revision cited by the paper.
Confirm that the checkout has no uncommitted files, then build the artifact
image while recording that exact revision:

test -z "$(git status --porcelain)"
docker build --build-arg SOURCE_REVISION="$(git rev-parse HEAD)" -f experiments/docker/artifact.Dockerfile -t ztai-artifact:latest .

Run all unit tests and reproduce the manuscript's principal E006, E009B,
E010-E013, and E020 result tables with one container command:

mkdir -p artifact-output
docker run --rm --tmpfs /tmp:rw,exec,nosuid,nodev,size=512m -v "$PWD/artifact-output:/output" --entrypoint python ztai-artifact:latest experiments/reproduce_principal_tables.py /output/run

The output directory contains raw CSV rows, aggregate CSV summaries, command
logs, and manifest.json with SHA-256 hashes and the source revision. A reduced
smoke run can append --smoke. Do not compare latency values across different
machines as if they were sampled from one performance population.

The separate E015, E017, and E018 supplemental suite remains available as:

docker run --rm --tmpfs /tmp:rw,exec,nosuid,nodev,size=512m -v "$PWD/artifact-output:/output" ztai-artifact:latest /output/supplemental --cycles 100

The offline suite does not contact SPIRE or cloud providers. It does not perform
E016 live-cloud validation or E019 independent validation. The live-cloud runner
requires a real short-lived JWT-SVID, an author-controlled Google Cloud or
Microsoft Azure sandbox, and explicit confirmation of one canary object write.
It must not be run against production resources.

the artifact container:

and volume isolation evidence, not physical multi-host validation.
